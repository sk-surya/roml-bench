Model-construction benchmark v1

How long does it take to build an equivalent linear model as the problem grows — ROML Python vs PuLP, Pyomo, and PyOptInterface, plus ROML Python vs native ROML core? Primary metric: populate_ms, the elapsed construction-API time from the first variable insertion into an already-created empty model through objective installation. Imports, data generation, solves, serialization, and report generation are excluded.

Measured findings (paired points only)

  • sparse_rows at paired size 1000000: fastest Python construction was Pyomo (median 1.05e+03 ms); PuLP 1.17x vs ROML bulk; Pyomo 0.62x vs ROML bulk; PyOptInterface 0.97x vs ROML bulk.
  • bess_96 at paired size 300: fastest Python construction was PyOptInterface (median 216 ms); PuLP 0.78x vs ROML bulk; Pyomo 0.59x vs ROML bulk; PyOptInterface 0.36x vs ROML bulk.
  • ROML binding overhead at sparse_rows 100000: Python scalar 350.59x vs native core; Python bulk 1.26x vs native core (median ratios, paired points only).
  • Censored points are shown as gaps, never extrapolated (1 stop events: timeout; see Data).

PyOptInterface is a thin direct wrapper around a HiGHS solver model, while ROML, PuLP, and Pyomo maintain separate modeling representations. The Populate time therefore measures elapsed user-facing construction-API work under each library's architecture — not identical internal work. See Methodology.
