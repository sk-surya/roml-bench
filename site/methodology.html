Methodology

This page states the exact benchmark contract, semantic boundaries, pins, and host provenance for run 20260908T192754Z-ai90-a645d57f.

Workloads

sparse_rows

Isolates primitive linear-model construction overhead with fixed sparsity. For size N: continuous variables x[0:N] with 0 <= x <= 5; R = floor(N/10) rows, each sum(x[10r+k], k=0..9) <= 10; objective min sum x. Variables N, constraints floor(N/10), row nonzeros 10·floor(N/10), objective nonzeros N.

bess_96

Realistic indexed linear algebra: T = 96 periods, dt = 0.25, leg efficiency eta = 0.95, power limit P = 2.0, energy limit E = 4.0, initial energy E0 = 2.0. Per battery: charge[t], discharge[t] in [0, P], energy[t] in [0, E]; energy[0] == E0; energy[t+1] == energy[t] + dt·(eta·charge[t] − discharge[t]/eta); charge[t] + discharge[t] <= P. Objective max dt·Σ price[t]·(discharge[t] − charge[t]) with a deterministic price vector uniform on [20, 80) generated once per run from seed 20260908 and shared across implementations. Per battery: 289 variables, 193 constraints, 577 row nonzeros, 192 objective nonzeros. No ROML mutable parameters are used: this milestone is model construction, not parameter updates.

Timed boundary

Primary metric populate_ms: the timer starts immediately before the first variable insertion into an already-created empty model/container and stops immediately after the objective is installed. Excluded: process startup, imports, canonical data generation, RNG, version detection, logging, validation, solver optimization, serialization, and HTML generation. container_init_ms is measured separately; user_build_total_ms = container_init_ms + populate_ms. The main scaling charts use populate_ms.

Implementations and construction paths

  • ROML Python (bulk) — ROML Python shaped/bulk path: Model.vars + add_linear_rows CSR (sparse_rows) or vectorized Model.add with one fused rm.dot objective call (bess_96, corrected in the forensic pass).
  • ROML Python (naive chain) — Naive scalar chain: Model.var + repeated `total = total + v`. Each `+` clones the accumulated expression and linearly scans its terms (O(n^2)); measures the naive path, not binding overhead.
  • PuLP — PuLP: LpProblem.add_variable_dicts + lpSum helpers. Validation solves use the bundled CBC binary.
  • Pyomo — Pyomo: ConcreteModel + indexed Var/Constraint rules + quicksum. Validation solves use appsi_highs.
  • PyOptInterface (scalar) — PyOptInterface formulation: scalar add_variable loop + per-row ScalarAffineFunction constraints + ExprBuilder objective, driven from B/T/prices with no shared CSR.
  • ROML Python (CSR ingest) — BESS matrix ingestion: one flat Model.vars with exact per-element bounds + add_linear_rows from the shared canonical CSR; flat v[i] namespace (ingestion diagnostic, bess_96 only).
  • PyOptInterface (matrix) — PyOptInterface matrix ingestion: add_m_variables per family + add_m_linear_constraints per sense group + ExprBuilder objective, backed directly by HiGHS (see methodology).

Python primary comparison uses each library's documented efficient public API while preserving workload mathematics and semantic naming (x for sparse_rows; charge, discharge, energy for bess_96). ROML Python exposes no public model-count introspection, so its structural counts are exact adapter construction bookkeeping; PuLP and Pyomo counts are library introspection. Mathematical equivalence is proven by the validation solve gate, not by counts alone.

Semantic boundaries

PyOptInterface's model is solver-backed: population calls insert directly into HiGHS. ROML, PuLP, and Pyomo maintain a separate modeling representation. populate_ms is elapsed user-facing construction-API work under each architecture, not identical internal work. Memory figures are child-process RSS (peak high-water mark) — a secondary metric, not allocator-independent efficiency evidence.

Process isolation and runtime controls

Every replicate runs in a fresh child process: import dependencies, apply thread limits, generate canonical input outside timing, run a tiny unrecorded warmup, create the empty model (container_init), time the full population, emit one machine-readable JSON record, exit. Implementation order is randomized per workload/size/replicate from the run seed. Children are pinned to one logical CPU when the platform allows; thread environment is limited (OMP_NUM_THREADS=1, OPENBLAS_NUM_THREADS=1, MKL_NUM_THREADS=1, NUMEXPR_NUM_THREADS=1, RAYON_NUM_THREADS=1).

Replicates, stop policy, statistics

Quick profile: 3 replicates, 15 s per-process wall limit. Standard profile: 7 replicates, 120 s hard wall limit, 16 GiB child RSS ceiling, plus a 60 s pilot budget (an implementation whose own first replicate exceeds it is stopped for larger sizes). Timeouts, RSS breaches, and errors are recorded as data; larger sizes stop for that implementation/workload; nothing is extrapolated. Summaries report median, p25, p75, min, max, MAD, and replicate count. Speedup is competitor_median / roml_median on paired points only.

Forensic pass (v2) addendum

The v1 report mixed two questions. The forensic pass splits them:

  • Formulation panel. Timed input is N (sparse) or B/T/prices/dt/eta/limits (bess). New arms: roml_python_naive_chain (the renamed v1 scalar path; O(n^2) chaining disclosed), pyoptinterface_scalar (scalar formulation with no shared CSR). The BESS bulk objective is one fused rm.dot(price_grid, discharge − charge) call over a precomputed contiguous grid.
  • Matrix-ingestion panel. Timed input is the shared CSR matrix, row bounds, objective vector, and variable bounds. Arms: ROML bulk (sparse), roml_python_csr (bess, flat namespace with exact per-element bounds), PyOptInterface matrix. PuLP/Pyomo expose no matrix API and are excluded here by design.
  • Phase decomposition. Adapters expose variables / constraints / objective phases timed separately inside the worker (Rust: --phase-breakdown).
  • Ingestion diagnostics. shuffled permutes in-row column order; duplicated doubles entries (2x nnz, recorded). Canonical only for leaderboards and speedups.
  • Named vs anonymous core. roml_core_rust_anon skips every .named() call to isolate name-registration cost.
